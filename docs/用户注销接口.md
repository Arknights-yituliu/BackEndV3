# 用户注销接口

两个接口均使用本站登录凭证，沿用现有 `Authorization` 请求头格式，由 `/auth/**` 拦截器鉴权。
用户身份取当前登录上下文，refresh token 取服务端 `uc:token:{uid}` 缓存，前端无需提供这两个字段。

## 1. 发送注销验证码

`POST /auth/user/account/send-delete-code`，无请求体。

后端调用用户中心 `POST /oauth2/account/send-delete-code`，JSON 为 `{"refresh_token":"服务端凭证"}`。
验证码发往用户中心当前绑定的邮箱；邮箱是否绑定及发送频率由用户中心校验。

## 2. 确认注销

`POST /auth/user/account/delete`，请求为 JSON：

```json
{"code":"012345"}
```

`code` 必须是 6 位数字字符串，保留开头的零。
后端调用用户中心 `POST /oauth2/account/delete`，JSON 为 `{"refresh_token":"服务端凭证","code":"012345"}`。
这是永久注销账户操作，用户中心保留游戏数据。

用户中心返回成功后，后端先将本地资料标记为已删除、状态设为 -1，再删除 TCL 令牌缓存和当前登录 token。
其他设备的旧登录 token 也会因本地资料已禁用而被鉴权拒绝。本站不删除游戏业务数据。
前端收到成功后清理本地登录凭证和 TCL access token，退出登录。

## 响应与失败处理

成功均返回本站统一响应：`{"code":200,"msg":"操作成功","data":null}`。
业务错误仍采用 HTTP 200，通过响应 `code` 判断是否成功。

- 缺少验证码：`39002`；验证码格式不合法：`10001`。
- 验证码错误、已过期、发送过于频繁、未绑定邮箱等上游业务错误，沿用 TCL 客户端返回 `60002`，`msg` 为对应原因。
- 缺少服务端 refresh token：`60002`，提示重新登录后重试。
- 用户中心返回 refresh token 无效（`90009`）时，仅清理 TCL 凭证缓存，本地会话保留。
- 验证码错误或上游请求失败时，不禁用本地资料，也不删除本站登录 token。

这些接口复用现有用户中心地址配置，无需新增配置项。
